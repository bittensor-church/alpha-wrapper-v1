## Agent 7 — first-principles

FINDING | contract: VaultReads | function: resolveValidators | bug_class: unvalidated-weight-sum
assumption: _alignToWeights assumes Σ_{i<last} weights[i] ≤ BPS_BASE so targets[lastIndex] = total - assigned cannot underflow; resolveValidators validates only length, MAX_VALIDATORS and hotkeys.length == weights.length.
violation: any IValidatorRegistry implementation (vault explicitly supports weighted registries, docs/hotkey-swaps.md) returns weights whose leading entries sum above 10000, e.g. [6000, 6000, 1] or [20000, 0].
path: registry.getValidators → resolveValidators (passes) → wrap / rebalance / _unwrapFromLiveSubnet(non-parked) → VaultAllocation.rebalance or deliverAndAlign → _alignToWeights → targets[lastIndex] = total - assigned → Panic(0x11) → every alpha deposit, rebalance and alpha exit reverts; only unwrapForTao and parked exits survive.
proof: weights = [6000, 6000, 1], total = 100 RAO: targets[0] = 60, targets[1] = 60, assigned = 120, targets[2] = 100 - 120 → underflow revert. [20000, 0]: targets[0] = 200, 100 - 200 reverts. Revert sits inside deliverAndAlign so unwrap for a non-parked position fails (whole tx reverts, no loss, no alpha exit). BasicValidatorRegistry cannot produce this; any other registry can, and the vault's own validation claims to reject malformed sets (ValidatorSetMalformed).
description: The registry can publish weights whose sum exceeds 10000, so _alignToWeights underflows and every wrap, rebalance and alpha unwrap reverts.
fix: Sum the weights in resolveValidators and revert ValidatorSetMalformed when the sum differs from BPS_BASE.
