## Agent 2 — access-control

FINDING | contract: CloneBase | function: initialize | bug_class: retained-staker-ownerless-hotkey-freeze
guard_gap: The clone sets setRejectStakingHotkeyGrowth(true) (CloneBase.initialize) but accepts third-party stake on any hotkey already on its list (chain: ensure_third_party_staking_hotkeys_can_grow returns Ok when hotkeys.contains(hotkey), pallets/subtensor/src/staking/stake_utils.rs:1568-1585). The vault's only remedy for an ownerless hotkey, StakeOps.ensureHotkeyHasOwner → tryAssociateHotkey, has no fallback.
path: attacker → transfer_stake(dest_coldkey = clone C, hotkey = attested V, netuid Y ≠ X, dust) → clone holds alpha on (V, C, Y) → any all-subnet swap_hotkey(V → V2, keep_stake=false) by V's owner → hotkey_swap_needs_split(C, V, X) true (other-netuid shares, stake_utils.rs:1534-1543) → hotkey_swap_stake_can_follow(C, V, V2, X) false because C rejects growth (stake_utils.rs:1546-1565) → C is a retained staker: its X alpha stays on V (swap_hotkey.rs:891-915, 1144, 1210) while Owner::<T>::remove(V) runs (swap_hotkey.rs:620-624) → attacker announce_coldkey_swap_v2(V) (dispatches.rs:2461-2500; ensure_coldkey_swap_destination only refuses when Owner contains V, swap_coldkey.rs:564) → every try_associate_hotkey(V) fails ColdkeySwapDestinationReserved (helpers.rs:136-143) → vault alpha on V cannot leave.
proof: Clone C records slot (V, V, 1_000 alpha) on subnet X. Attacker pays one chain minimum transfer of Y alpha onto (V, C, Y). V's owner does an all-subnet carry swap V→V2. Result: 1_000 alpha stays on V, getHotkeyOwner(V) = (false, 0), getHotkeySuccessor(V, X) = V2. Attacker reserves V for 0.1 TAO (SubtensorInitialKeySwapCost, runtime/src/lib.rs:975); reservation lives 5d+1d and is renewable at exactly that block (swap_coldkey.rs:151-158, dispatches.rs:2480-2486). Vault: resolveBacking reads balance 1_000 ≥ tracked → not short; syncBacking → BackingUnchanged. assignActives: funded slot, hasOwner(V) false → retired = V; wrap, rebalance → AttestedHotkeyRetired; partial unwrap → AttestedHotkeyRetired; full-supply unwrap → ensureHotkeyHasOwner(V) → tryAssociateHotkey reverts; unwrapForTao → same; registry update to V2 → consolidateRotatedStake → move(V→V2) → ensureHotkeyHasOwner(V) → same revert. Chain also refuses exits from V: transition_stake_internal requires hotkey_account_exists(origin_hotkey) (stake_utils.rs:1975-1978), remove_stake too (remove_stake.rs:164). No shortfall declared because alpha is located, so recovery never applies. Without the reservation step the dust still pins the clone's stake to the retired hotkey after every routine carry swap until the registry publishes V2 and the vault's claim of V succeeds.
description: An attacker who parks dust on another subnet under a recorded hotkey makes the clone keep its alpha on that hotkey through a swap, then reserves the ownerless hotkey, so no holder can exit.
fix: Remove setRejectStakingHotkeyGrowth(true) from CloneBase.initialize so the clone follows hotkey swaps while its list is under the third-party cap, and rely on replaceClone for a filled list.

LEAD | contract: AlphaVault | function: constructor | bug_class: vault-coldkey-staking-list-exhaustion
code_smells: ensureHotkeyHasOwner runs tryAssociateHotkey as the vault; create_account_if_non_existent (helpers.rs:128-160) pushes every claimed hotkey onto the vault coldkey's StakingHotkeys after ensure_staking_hotkeys_can_grow (cap 256, lib.rs:105). The vault never stakes/unstakes under its own coldkey, so maybe_remove_staking_hotkey never prunes; the list only grows.
description: After the vault claims 255 ownerless hotkeys over its lifetime, every later ensureHotkeyHasOwner call reverts with TooManyStakingHotkeys and the affected positions cannot move. Frequency of owner-record removal in production unverified.

LEAD | contract: CloneFactory | function: deployCloneOwner | bug_class: reserved-candidate-address
code_smells: _requireClean does not check the coldkey-swap destination reservation. CloneOwner constructor's tryAssociateHotkey(clone coldkey) is refused with ColdkeySwapDestinationReserved for a reserved address (helpers.rs:136-140). A front-runner can reserve the predicted clone/mailbox coldkey for 0.1 TAO and make createMailbox revert.
description: An attacker who reserves a predicted clone address as a coldkey-swap destination makes createMailbox revert for that UID. The caller retries with a fresh UID; impact is one wasted transaction per 0.1 TAO.

Verified clean: every clone function onlyWrapper, wrapper set in deployment tx; CloneFactory onlyVault; registry onlyOwner with renunciation disabled; vault entry points act only on msg.sender's mailbox/shares; keeper functions perform same-subnet moves at 0 fee (stake_utils.rs:1440-1500); precompile calls signed as caller's mapped account (precompiles/src/staking.rs:497-560, extensions.rs:117).
ORCHESTRATOR CORRECTION (post-gate): agent-2 FINDING retained-staker-ownerless-hotkey-freeze demoted to LEAD. The all-subnet swap path (perform_hotkey_swap_on_all_subnets_prepared, swap_hotkey.rs:655-664) passes retained = BTreeSet::new() and rename_all = true, so no staker is retained and all stake moves to the new hotkey; Owner removal at :624 therefore never coexists with stake under the old hotkey. The per-subnet path (swap_hotkey_on_subnet, :712-850) does retain growth-rejecting stakers but never removes Owner (:772 commented out). Agent 7's calibration note was correct.
